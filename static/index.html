运行时机制

四个机制各自解决的问题。

① 队列合并（coalescing）

每个 (租户, key) 只保留一个待处理槽位；同对象的连续更新就地合并，最新版本胜出、保留最早入队时间。风暴从“每更新占一槽”降为“每对象一槽”。

② 按键串行（per-key serialization）

同一 key 永远不会被两个 worker 并发处理，不同 key 仍可并行；避免乱序提交对同一对象的状态竞争。

③ 指数退避（backoff + jitter）

失败事件进入全局延迟堆，按 base·2ⁿ 加对称抖动退避；超过最大尝试次数进死信队列。已被新版本超越的失败尝试直接判过期，不再浪费重试。

④ 租户公平（DRR + 并发上限）

每租户独立 FIFO，Deficit Round Robin 按配额轮转调度，并限制单租户可占用的 worker 数；持续风暴无法饿死健康租户。

⑤ 过期版本保护（version CAS）

状态提交是版本号 compare-and-swap：重试的旧版本 ≤ 已提交版本时被拒绝（StaleVersionError），旧重试永远无法覆写新状态。

⑥ 基线对照

naive-fifo 共享同样的安全保证（串行、CAS、退避），但不合并、不做公平调度——用它量化前四个机制带来的收益。
